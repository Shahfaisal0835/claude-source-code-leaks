# Context Management in AI Coding Assistants

> **Note:** This document is educational and analytical. All concepts are derived from publicly available research and documentation. No proprietary or confidential material is included.

---

## Overview

The **context window** is the fixed-size memory that a large language model uses to process input and generate output. For AI coding assistants, managing this window efficiently is critical: a well-managed context contains exactly the information needed to complete the current step, while an unmanaged context quickly fills with stale, irrelevant content that degrades model performance and increases cost.

---

## 1. What Goes Into the Context Window?

A typical context window for an AI coding assistant contains multiple sections:

```
┌─────────────────────────────────────────┐
│  System Prompt                          │  (fixed, always present)
│  ─ Role, rules, tool definitions        │
├─────────────────────────────────────────┤
│  Persistent Memory / Background         │  (loaded at session start)
│  ─ Project facts, user preferences,     │
│    coding conventions (e.g. CLAUDE.md)  │
├─────────────────────────────────────────┤
│  Conversation History                   │  (grows over time)
│  ─ Prior user messages and responses    │
│  ─ Tool calls and results               │
├─────────────────────────────────────────┤
│  Current Context (injected dynamically) │  (changes per task)
│  ─ Relevant file contents               │
│  ─ Current error messages or test output│
│  ─ Git diff or recent changes           │
└─────────────────────────────────────────┘
```

The total must fit within the model's context window limit (e.g., 200,000 tokens for Claude 3.5).

## 2. Context Window Strategies

### 2.1 Sliding Window

The simplest strategy: keep only the most recent N turns of conversation history. Older turns are dropped entirely.

**Pros:** Simple to implement  
**Cons:** The model loses awareness of decisions made earlier in the session

### 2.2 Summary + Recent Turns

Keep a running **summary** of earlier turns, plus the full text of the most recent turns.

```
[SUMMARY]: The user asked to refactor the UserService class to use DI. 
We updated the constructor and 3 call sites in tests. 
The integration test is still failing due to a missing mock.

[RECENT TURNS]
User: The mock still isn't being injected correctly.
Assistant: Let me check the test setup...
```

**Pros:** Preserves high-level continuity  
**Cons:** Summaries may lose important detail; requires an extra model call to generate

### 2.3 Retrieval-Augmented Context

Instead of including all files, use **semantic search** to retrieve the most relevant code snippets dynamically.

```
Query: "authentication middleware"
→ Search: cosine similarity over codebase embeddings
→ Retrieve: top-5 most relevant code chunks
→ Inject into prompt: only those chunks
```

**Pros:** Scales to large codebases  
**Cons:** Requires embedding infrastructure; retrieved chunks may miss important context

### 2.4 Explicit File Mentions

The user or the model explicitly names which files are in scope. Only those files are loaded into the context.

```
User: @src/auth/middleware.ts Fix the JWT expiry check
→ Load only middleware.ts (and directly imported modules)
→ Include in prompt
```

**Pros:** User controls context; predictable  
**Cons:** User must know which files are relevant

## 3. Token Budgeting

AI coding assistants must track token usage across all context sections:

| Section | Typical Budget |
|---|---|
| System prompt | 1,000 – 5,000 tokens |
| Persistent memory | 500 – 2,000 tokens |
| Conversation history (summarized) | 2,000 – 10,000 tokens |
| Current file contents | 5,000 – 50,000 tokens |
| Tool results | 500 – 5,000 tokens per result |
| Response buffer | 4,000 – 16,000 tokens |

When a section exceeds its budget, the orchestrator applies truncation or summarization. The model itself may also be given explicit instructions about its token budget:

```
You have approximately 8,000 tokens remaining in your context window.
Be concise in your reasoning and prioritize completing the current task.
```

## 4. File Content Management

### 4.1 Lazy Loading

Files are loaded into the context only when they are needed, not at session start. This prevents wasting context on irrelevant files.

### 4.2 Content Truncation

When a file is too large to include in full:

- Include only the most relevant section (e.g., the function being edited)
- Include the file's structure (e.g., class/function names) and let the model request specific sections
- Include a summary generated by the model on a previous turn

### 4.3 Diff-Based Context

Instead of re-sending the entire file after each change, send only the diff:

```diff
- function getUser(id: number) {
+ function getUser(id: string) {
    return db.users.findById(id);
  }
```

This is more token-efficient for iterative editing tasks.

## 5. Memory Files (e.g., CLAUDE.md)

Many AI coding tools support a **memory file** (e.g., `CLAUDE.md`, `AGENTS.md`, `.cursor/rules`) that is automatically loaded at the start of each session. This serves as long-term, persistent memory:

```markdown
# Project Memory

## Stack
- Node.js 20, TypeScript 5.4
- PostgreSQL 15 with Prisma ORM
- Jest for testing

## Conventions
- Use named exports, not default exports
- All API handlers must validate input with Zod
- Prefer `async/await` over `.then()` chains

## Known Issues
- The `EmailService` class has a race condition under high load (tracked in issue #142)
```

The model reads this file at the start of each session and uses it to maintain continuity across sessions without relying on conversation history.

## 6. Context Hygiene Best Practices

For developers building on or working with AI coding assistants, maintaining good **context hygiene** improves reliability:

1. **Keep memory files up to date** – Stale information in `CLAUDE.md` can mislead the model.
2. **Close irrelevant files** – Some tools track open editor tabs as context; close files not related to the current task.
3. **Summarize long tasks** – For very long tasks, explicitly ask the model to summarize progress before continuing.
4. **Avoid redundant tool results** – If a file hasn't changed, don't re-include its full content.
5. **Use scoped tasks** – Break large tasks into smaller sessions to avoid context overflow.
